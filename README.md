# Joomla K2 Finder 1.1

Node.js 22+ CLI для **пассивного** поиска публичных признаков Joomla и K2 на сайтах. Создаёт полный CSV-отчёт и отдельный список российских кандидатов для ручной проверки. Без npm-зависимостей и платных API.

> **Не сканер уязвимостей.** Читает только публичный HTML, соблюдает `robots.txt`, ограничивает скорость, не авторизуется, не отправляет формы, не подбирает директории и не проверяет CVE. Признаки K2 не доказывают точную версию Joomla, а версия сайта не доказывает наличие уязвимостей.

## Быстрый старт

```bash
node --version                  # требуется Node.js 22+
node finder.mjs --input domains.txt --output results.csv --leads leads.csv --ru-only
node --test
```

Для более точной версии можно включить опциональную проверку общедоступного манифеста ядра Joomla (только когда разрешает `robots.txt`):

```bash
node finder.mjs --input domains.txt --output results.csv --leads leads.csv --ru-only --manifest
```

## Входные данные

TXT (по одному домену/URL на строку) или CSV со столбцом `domain`, `url`, `site`, `website`, `домен`, `сайт`.

Для ручной классификации компаний можно использовать `companies.example.csv`:

```csv
domain,company_name,business_type
company.ru,Пример компании,business
news.ru,Пример СМИ,media
example.com,Example Inc,business
```

`business_type` задаётся **вручную**, значения: `business`, `media`, `ngo`, `government`, `personal`, `other` или `unknown` (по умолчанию). Скрипт **не утверждает**, что компания является действующей или имеет бюджет на миграцию. Это нельзя надёжно определить автоматически из одного заголовка страницы.

## Два отчёта

- `results.csv` — все проверенные домены, ошибки и подтверждающие публичные URL.
- `leads.csv` — только успешные проверки доменов `.ru` и `.рф`, где видны сигнатуры K2 и которые не помечены как `media`/`ngo`/`government`/`personal`/`other`. Строки `business_type=unknown` включаются с `lead_priority=review`, то есть **требуют ручной проверки**, а не считаются готовыми клиентами.

Основные поля:

| Поле | Значение |
| --- | --- |
| `joomla_detected`, `k2_detected` | `yes` — признак найден; `no` — не найден на проверенных страницах; `unknown` — проверка не завершилась |
| `k2_confidence` | `high` — маршруты/ресурсы `com_k2`; `medium` — только `media/k2`; `unknown` — нет признаков |
| `joomla_version` | Точная версия при наличии явного источника или предположение (`3.x`, `2.5`, `4+`) |
| `version_confidence` | `high`, `medium`, `low`, `conflict`, `unknown` |
| `technical_priority` | Приоритет технической проверки: `high`, `medium`, `review`, `low` |
| `lead_priority` | Коммерческий приоритет: `high`, `medium`, `review`, `low`; высокий только после ручного `business` и подходящих техпризнаков |
| `business_type`, `company_name` | Значения из входного CSV или прошлой строки отчёта, не автоматическая идентификация юридического лица |
| `scan_status`, `error`, `robots_status` | Что удалось проверить, почему запрос не удался |
| `evidence`, `checked_at` | Сигнатуры с URL и время проверки |
| `priority` | Совместимый со старым отчётом псевдоним `technical_priority` |

Не путайте `no` с доказательством отсутствия технологии: скрипт проверяет несколько страниц, а не весь сайт.

## Продолжение сканирования и совместимость с 1.0

По умолчанию скрипт читает существующий `results.csv` и **не сканирует повторно** сайты со статусом `ok`, сохраняя имеющиеся записи. Сохранения атомарны (через временный CSV), после каждого нового сайта. Старые значения `true`/`false` преобразуются в `yes`/`no`; для старых строк с ошибкой оба поля становятся `unknown`.

```bash
# Продолжить список без повторной проверки готовых строк
node finder.mjs --input domains.txt --output results.csv --leads leads.csv --ru-only

# Попробовать заново ранее неудавшиеся проверки (но не обходить robots.txt)
node finder.mjs --input domains.txt --output results.csv --leads leads.csv --retry-errors --ru-only

# Начать отчёт с чистого листа, игнорируя предыдущий CSV
node finder.mjs --input domains.txt --output results.csv --leads leads.csv --fresh --ru-only
```

`--max-sites` ограничивает **количество новых сканирований за запуск**, по умолчанию 100. Существующие удачные записи не расходуют этот лимит. Для повторного анализа ранее успешно проверенного сайта используй `--fresh` с подходящим отдельным входным списком. Рекомендуется сохранять резервную копию отчёта перед `--fresh`.

### Параметры

```text
--input PATH        входной TXT/CSV (обязательный)
--output PATH       полный отчёт, по умолчанию results.csv
--leads PATH        список кандидатов, по умолчанию leads.csv
--ru-only           проверять только .ru и .рф (IDN поддерживаются)
--retry-errors      повторить закешированные ошибки; не обходит запреты
--fresh             игнорировать старый отчёт
--manifest          публичный манифест Joomla, если доступен и разрешён
--delay MS          минимальная пауза между запросами к сайту, >=1000, default 1500
--timeout MS        таймаут запроса, default 10000
--max-pages N       до N публичных HTML-страниц на домен, 1..5, default 3
--max-sites N       не более N новых сканирований, default 100
--help              показать справку
```

## Ограничения и безопасность

- Фильтр `.ru`/`.рф` **не подтверждает российскую регистрацию компании**: это только отбор доменных зон.
- Встроенный `robots.txt` парсер проверяет `Allow/Disallow`, не заменяет профессиональный crawler с полной поддержкой всех расширений правил.
- Текущий скрипт проверяет DNS и блокирует частные/локальные адреса, однако не является полной защитой от DNS rebinding. Используй только проверенные публичные домены, не запускай в доверенной внутренней сети.
- Коды 403/429, CAPTCHA, нестабильное соединение, запрещающий robots и отсутствие признаков — разные ситуации; смотри `scan_status` и `error`.
- Не выполняет поиск новых доменов, CVE-проверку и массовые рассылки.
- Значения CSV экранируются и нейтрализуют формулы при открытии в табличных редакторах.
- Решение о коммерческом обращении и любые заявления об уязвимостях требуют ручной проверки и соблюдения законодательства о рассылках.
